# dsheng

两表一单本地经营分析工具，包含 Tauri 桌面应用、Rust CLI、Agent Skill 和中文使用手册。

当前本地修复版本为 0.1.9；功能、构建方法、验证范围和已知限制见 [工程交接文档](HANDOFF.md)。仓库中的计划与设计资料包括：

- [实施计划](两表一单-本地经营分析工具实施计划.md)：产品边界、SQLite、Provider、`dsheng` CLI、Agent Skill、跨平台交付和验收标准。
- [整体计划复审与交接门禁](docs/plan-readiness-review-2026-10-30.md)：保留问题发现与交接门禁；本次已把数据/周期、任务/历史、Provider/设置/交付及提示词上下文的决策补入专门合同，当前仍有新版真实内容验收门禁。
- [完整实施规格](docs/specs/) 与 [机器合同/验收算例](contracts/v1/)：工程实现应遵循的字段、算法、生命周期、预算、CLI、平台及验收依据。
- [交互原型](prototype.html)：使用全量虚构数据展示数据源、经营分析、图表、独立经营问题诊断、任务详情、任务编辑、进度时间线、Provider 和系统设置。
- [内置提示词与输出契约](crates/dsheng-core/prompts/README.md)：任务单及 5WHY / 5W / 5W2H 的 system/user 模板、JSON Schema、装配方式和逐版本真实测试记录；当前任务数量与语言偏好修订已获用户授权，版本与验证范围单独记录。

原型中的企业、目录、文件、金额、岗位和 Provider 值均为虚构演示数据，不来自真实业务文件。

任务单支持直接手动新建任务、增删行动项，以及修改 AI 生成后已应用的任务；保存与编辑只在本地执行，不需要 Provider。

经营问题诊断与任务单是独立模块：诊断按所选框架形成报告；任务单依据经营数据制定目标与行动，使用 SMART 校验目标，可选参考诊断报告。当前任务 prompt 为 2.5、诊断 prompt 为 2.1：保留简体中文展示偏好，任务及步骤按证据展开，不再限定一项；任务输入带入相关已应用任务的当前执行记录，以及用户显式选择的完整诊断背景；任务输出 schema2、诊断 turn/report schema3、输入/context2 保持原形状。新提示词尚未调用真实 Provider，任务覆盖及中文遵循效果待实际使用验证。信封继续采用 C 方案：严格提示词要求优先，适配层仅对唯一裸任务对象做带 envelope_locally_reconstructed 标记的本地包装。

历史基线任务 prompt2.3 / 诊断 prompt2.0 于2026-11-02获批冻结，累计确认派发44次真实 glm-5.3 请求（另1次状态未知）；2.3完整复测批19个场景通过当时合同与所审语义。该历史验收及原失败、未验证事项保留在版本记录中，不作为当前提示词版本的真实模型验收。旧的剩余调用授权已经作废。

公开仓库和规划产物同步不代表产品已经实现或正式发布。桌面安装包、便携包、独立 CLI 等正式交付物须完成产品验收并获得相应发布授权后，才能发布 GitHub Release。
