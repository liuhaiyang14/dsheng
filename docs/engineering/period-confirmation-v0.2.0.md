# v0.2.0：确认页与月度期间保存修复

本轮针对导入后无法创建期间、确认表单含义不清、旧提示误导等问题修复，应用版本保持 `0.2.0`。输入适配规则单独升为 `xsd_trade_v1` version 2；两表输出合同仍是 `two_tables_v1`。

## 操作与结果

1. 在数据源选择与文件结构匹配的输入模板，扫描原始文件目录。贸易/制造业单据使用内置单据模板；已保存的企业模板选择可恢复。桌面端幂等初始化缺少的常用指标，已有自定义指标版本不变。
2. 点击“确认文件用途和关键列”，在独立全宽表单中核对各文件用途、金额列、归属日期列及有效单据条件。辅助资料仅供查阅。按文件和指标分别确认金额税口径；未知或混合税率保持待确认，不能假定税率。
3. 点击页眉“生成期间”，选择扫描识别出的月份，点击“生成并保存期间”。成功后月份出现在页眉列表；已有月份再次运行时主动生成新修订版，旧版本保留。
4. 缺工时、目标、分类和税口径只影响相关指标，不填 0。其他月份的待确认金额不清空本月已确认值。同窗口未确认的贡献会阻止残缺合计冒充完整实绩。

## 根因与修复

- Excel 类型化日期曾被读取为序列数字；现在依据工作簿 1900/1904 日期体系转换，排除时长、裸时间和伪闰日。扫描与分析共用文本时间戳解析，工资年月保留完整月区间。
- 全新档案没有指标目录，正常确认后可能生成空指标结果；桌面扫描与分析入口补齐缺少的默认指标，保留用户已有定义。
- 原确认表单与提示挤在一行，内部类型名及单列选择含义不清；现在按文件和用途展开明确字段，标准模板保留自动识别列，手工修正仅覆盖指定角色，连续修改按来源、工作表和角色合并，并展示全部已保存列修正。
- 全局税口径阻断曾把无关金额一并清空；现在按指标保存显式税确认和待补期间。审核状态关键列缺失或空值不计入实绩。
- 命中明细规则的工作表不会再次走通用表计算，防止自定义模板重复加总。
- 源字段快照按来源和指标汇总为桌面四字段视图，避免成功生成后因内部记录缺少显示字段而崩溃。

真实源回归已完成：11 个文件识别 23 个月，9 月人工费和付款金额与独立 Decimal 核对一致；含税销售及成本税口径未确认时保留待补。该测试默认忽略以免依赖开发机私人文件，已按上述 opt-in 命令单独执行。所有真实源只读；没有修改用户软件数据库。

Playwright 在 1280×900 下执行真实 React 页面，使用明确的合成数据输入：确认用途与税口径 → 保存 → 选择月份 → 生成保存 → 页眉出现月份；没有页面异常或横向溢出。此证据不替代 Tauri 集成；没有启动已安装 App，也没有调用 Provider。`prototype.html` 的保存行为明确属于原型演示，不写 SQLite。
